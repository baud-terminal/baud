# VT100 / ANSI

The set every terminal must implement. No application can be assumed to work
without these.

- **Implementation:** `baud-core/src/{write,ops,paint}.rs`
- **Tests:** `baud-core/tests/vt100/`
- **Conformance:** `vt100` (44 caps), `vt102` (49), `ansi` (63) — all passing
- **Sources:** `[[source: ecma48]]`, `[[source: ctlseqs]]`,
  `[[source: williams]]`

Per-operation status is in [../vt-coverage.md](../vt-coverage.md). This records
the parts that are easy to get subtly wrong.

## ED and EL split at the cursor

`[[source: ecma48]]` § 8.3.39: for `Ps = 0`, "the active presentation position
**and the character positions up to the end of the page**"; for `Ps = 1`, "from
the beginning of the page **up to and including** the active presentation
position".

The cursor's own row is therefore erased *partially*. baud erased whole rows
until this was read — so `CSI 0 J` with the cursor mid-line destroyed the text
to its left. Every ED test in the suite happened to put the cursor at column 0,
where the two behaviours coincide, so none of them could see it. It surfaced
while implementing VT52's `ESC J`, which is the same operation.

Every test in `tests/vt100/erase.rs` now erases from a **non-zero column**.

## LF is index, not newline

LF moves down and keeps the column unless LNM is set. `[[source: ctlseqs]]`
lists mode 20 as reset, so that is the default. Conflating the two makes every
line of a stream march rightwards.

`ESC E` (NEL) is the one that does both, and `ESC D` (IND) is LF's ANSI twin.

## IRM inserts; it does not overwrite

`[[source: ecma48]]` § 8.3.64. IRM was recorded and reported by DECRQM while
nothing in the write path read it, so an application got overwrite and was told
it had insert — two of the three non-negotiable rules broken at once. Under IRM
the write opens a gap of the character's width at the cursor through
`insert_cells`, the shift `ICH` uses, and writes into it
(`baud-core/src/paint.rs`).

## Autowrap has a deferred-wrap position

With DECAWM set, the cursor sits one *past* the last column after a character
lands there. That is a sentinel the next write consumes, not a position:
`[[source: vt510-decawm]]` puts the cursor *at* the right border. `Term::cursor`
clamps, so CPR never reports a column the page does not have.

## Tab stops are a table

HTS, TBC, CHT and CBT are meaningless without one, and `HT` after `CSI 3 g`
must run to the right margin rather than to the next multiple of eight.

## Charsets are designated and translated, and DEC's is one short

`ESC ( ) * +` designate G0–G3; SO and SI invoke G1 and G0. A byte written under
the DEC line-drawing set reaches the cell **translated, and flagged**
(`CellFlags::GRAPHICS`), so a copy of `─` is `─`. DEC defines 32 positions,
`0x5F..0x7E` (`[[source: vt100-ug-ch3]]` Table 3-9), and none of the DEC texts
read gives a codepoint for any of them; baud has 31, `0x60..0x7E`, with
`[[source: foot-vt100-0]]`'s codepoints. **`0x5F` "Blank" stays `_`**: an open
departure, U+0020 or U+00A0 being the owner's call. The UK and national sets
translate through `[[source: xterm-charsets]]`. See
[../protocol-decisions.md](../protocol-decisions.md).

This section said a byte under the line-drawing set reached the cell untranslated
because `dec-special-graphics` was `gated`. The table landed in f297b21, and the
DEC pages are pinned and `retrieved` now.
