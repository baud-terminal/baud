# Features

What baud does for you today, by area. Every line is backed by a test or a
measurement in the repository, and the build fails if that proof disappears,
so this list cannot quietly fall out of date. What is coming next is on the
[roadmap](../roadmap.md).

Lines with no mark work in the macOS app and in the shared terminal core,
which the Linux version also runs; the Linux version has run only headless so
far. *macOS* marks what only the macOS app does, and *Linux, headless so far*
what only the Linux version does. **Partly** says what part is missing, and
**For now** marks a stopgap until its replacement lands.

## Programs just work

Shells, editors and full-screen programs get the terminal they expect, and a broken one can't upset it.

- **No wrong answers** — A question baud cannot answer truthfully gets no reply rather than a wrong one, and a setting baud does not have is reported as unknown, never as off. <sub>[proof](../../baud-core/tests/color_scheme.rs) · [reference](../vt-coverage.md#tier-2--vt220--vt420)</sub>
- **A VT420's questions, answered** — Programs that ask a VT420's status questions get true answers: where the cursor is and on which page, whether a printer is there, the keyboard, the locator and stored macros. They can also read back the cursor's state, the tab stops, the colour table and the terminal's whole state in one report, and put any of them back later. <sub>[proof](../../baud-core/tests/vt420/reports.rs) · [reference](../vt-coverage.md#tier-2--vt220--vt420)</sub>
- **xterm's own settings** — Programs can switch xterm's own settings and ask which are on: jumping to the live screen on output or on a key, reverse wrap past the left margin, hiding the scrollbar, copying a selection to the clipboard, keeping a selection's text to copy after a program writes over it, and the alternate-screen variants. <sub>[proof](../../baud-core/tests/xterm_resources.rs) · [reference](../vt-coverage.md#csi-operations)</sub>
- **Notifications and progress bars from programs** — A build or a long command can post a desktop notification when it finishes, with a title, a body and buttons, shown while baud's window is in the background or whenever the program asks; and it can show a progress bar, in the Dock on macOS. A flood of them is held to four at once and then one a second, and `[screen] notifications = "off"` turns them off. **Partly:** on Linux a program's icon shows only as a PNG, not yet as a JPEG or GIF; iTerm2's attention fireworks are not drawn; and on macOS a program that asks hears a notification went out before you have allowed them. <sub>[kitty desktop notifications](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use) · [proof](../../baud-core/tests/notifications.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **Programs written for iTerm2** — A program or shell script written for iTerm2 can change the cursor's shape, erase the history, tell the title which folder and host it is in, copy text to the clipboard, recolour the text, the background, the cursor, the selection and the sixteen colours, ask for your attention, ask how big a cell is, mark a line that Cmd-Up and Cmd-Down stop at, post a notification, switch to Unicode 8's character widths, and set user variables, whose values baud never sends back to a program that asks, so a remote program cannot read what your shell set. A message that would bring the window to the front, switch your settings or upload your files is refused. **Partly:** iTerm2's badge, cursor guide, inline images and file downloads, a notification's subtitle and picture, annotations, foldable blocks and Touch Bar labels are not built yet. <sub>[proof](../../baud-core/tests/iterm.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **A damaged escape code can't clear your screen** — A broken or cut-off control sequence is thrown away instead of being half-obeyed, and hidden data in the stream is never printed. <sub>[proof](../../baud-core/tests/esc_abandons.rs) · [reference](../vt-coverage.md#tier-0--the-parser-state-machine)</sub>
- **No flooding memory** — A giant title, link or other string a program sends is cut to size, so it can't fill memory. <sub>[proof](../../baud-core/tests/xterm/osc.rs)</sub>
- **Compatible with what programs expect** — baud answers to the VT100, VT220, VT420 and xterm feature sets, checked against the original manuals, and works under every common terminal type from xterm-256color to vt100. <sub>[proof](../../baud-core/tests/conformance/input_caps.rs)</sub>
- **Programs can tell what they are talking to** — A program that asks gets baud's name and version, and the VT100's original question gets the same answer as the modern one. <sub>[proof](../../baud-core/tests/xterm/keypad_version.rs) · [reference](../vt-coverage.md#csi-operations)</sub>
- **One letter, two meanings, kept apart** — A program asking to highlight a region no longer scrolls the screen: two controls that share a letter are told apart by their arguments. <sub>[proof](../../baud-core/tests/conformance/spec_inventory.rs) · [reference](../vt-coverage.md#csi-operations)</sub>
- **Cursor movement and editing** — Cursor moves, inserting and deleting, erasing, tab stops, repeats and the alignment test behave as programs expect. <sub>[reference](../vt-coverage.md#csi-operations)</sub>
- **Rectangle editing** — Programs can copy, fill, erase and change the styles of a rectangle of the screen in one go, and read back its checksum, as on a VT420. <sub>[proof](../../baud-core/tests/vt420/rect_ops.rs) · [reference](../vt-coverage.md#tier-2--vt220--vt420)</sub>
- **Sideways scrolling and every tab stop** — Programs can slide the screen's text left or right, clear every kind of tab stop, and set line tab stops for vertical tabs. <sub>[proof](../../baud-core/tests/vt100/scroll_columns.rs) · [reference](../vt-coverage.md#csi-operations)</sub>
- **A soft reset keeps you where you were** — A soft reset leaves a full-screen program on its screen, with its history and mouse tracking. <sub>[proof](../../baud-core/tests/xterm/soft_reset_scope.rs) · [reference](../vt-coverage.md#tier-2--vt220--vt420)</sub>
- **Protected text and saved settings** — Text a program protects survives its selective erase, an area it fences off the ISO way survives every erase, and programs can save and restore their own settings. <sub>[proof](../../baud-core/tests/vt220/selective_erase.rs) · [reference](../vt-coverage.md#tier-2--vt220--vt420)</sub>
- **Cursor save and restore** — Saving the cursor keeps its position, colours, wrap, origin and protection, and a position saved on the main screen stays on its text when the window is resized. **Partly:** two of the character-set details are not saved yet. <sub>[proof](../../baud-core/tests/saved_cursor_per_screen.rs) · [reference](../vt-coverage.md#esc-sequences)</sub>
- **VT100 to VT420 levels** — A program can ask for VT100, VT220, VT320 or VT420 behaviour and for 7- or 8-bit control codes, and read back which it has; baud then does only what that terminal did, down to the keys, and a reset returns to VT420 with 7-bit codes. <sub>[proof](../../baud-core/tests/conformance_level.rs) · [reference](../vt-coverage.md#tier-2--vt220--vt420)</sub>
- **132 columns when a program asks** — A program that asks for 132 columns, and is allowed to, gets a wider window, and a reset puts your width back. *macOS.* <sub>[proof](../../baud-app/src/width.rs) · [reference](../vt-coverage.md#csi-operations)</sub>
- **Exact page widths** — Programs can ask to keep the screen across a column change, or for an exact page width. **Partly:** both are honoured in part; each row names the part. <sub>[reference](../vt-coverage.md#csi-operations)</sub>
- **VT52 mode** — Very old software that speaks the VT52's language, keyboard included, still runs. <sub>[proof](../../baud-core/tests/vt52/sequences.rs) · [reference](../vt-coverage.md#esc-sequences)</sub>
- **8-bit replies for programs that ask** — Replies and keys switch to 8-bit control codes when a program asks. <sub>[proof](../../baud-core/tests/vt220/replies.rs)</sub>
- **Each command's result beside its prompt** — With `[screen] exit_status = "on"`, a mark beside each prompt your shell marks says how its command ended: a filled dot for success, a cross for failure and a ring for a cancelled one, in your theme's blue, red and grey. The marks have a column of their own, so they never cover text, and they stay with their prompt as you scroll, resize or read back. <sub>[proof](../../baud-render/tests/status_marks.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>

## Speed

Measured on real recordings and real keystrokes, with the numbers kept in [MEASUREMENTS.md](../../MEASUREMENTS.md).

- **Takes in output fast** — On real recorded program output, baud's core was faster than ghostty's and alacritty's on all nine recordings, from 1.19 to 5.80 times ghostty's rate; on the Chinese, Japanese and Korean recordings baud also does more work, grouping every character. <sub>[measured](../../MEASUREMENTS.md#against-other-implementations-on-real-capture)</sub>
- **Ahead through a real terminal connection** — On one Mac, through the same kind of connection a shell uses, baud led four other terminals on four of five recordings and used the least CPU on all but one. *macOS.* **For now:** measured before scrollback existed and not taken again since. <sub>[measured](../../MEASUREMENTS.md#five-terminals-through-a-pty)</sub>
- **What you type shows before the shell answers** — At a prompt your shell marks, a typed character is drawn about 3 ms sooner, and quietly taken back if the shell shows something else. *macOS.* <sub>[proof](../../baud-render/tests/predicted.rs) · [measured](../../MEASUREMENTS.md#a-keys-echo-drawn-before-the-pty-answers-row-9)</sub>
- **Keys first, even during a flood** — A key typed while a program streams output is drawn at once, about 2.8 ms sooner, instead of waiting for the next frame. *macOS.* <sub>[measured](../../MEASUREMENTS.md#pacing-a-keystrokes-frame-by-completion-row-6)</sub>
- **About 3 ms from key to screen** — A keystroke reaches the screen in about 3 ms through cat on a 120 Hz Mac, and baud can print the figure for your own machine (`BAUD_KEYLAT=1`). *macOS.* <sub>[proof](../../baud-app/src/latency.rs) · [measured](../../MEASUREMENTS.md#keystroke-to-pixel)</sub>
- **Quiet when idle** — An idle window draws nothing and uses about half a percent of one core; a steady cursor costs no frames at all. *macOS.* <sub>[proof](../../baud-app/src/caret.rs) · [measured](../../MEASUREMENTS.md#idle-cpu-row-11-measured-no-change)</sub>
- **No half-drawn screens** — Programs that redraw in one go, such as btop, neovim and helix, never show a half-finished screen, and a program that stalls can't hold the window for more than 33 ms. <sub>[synchronised output](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use) · [proof](../../baud-core/tests/xterm/embedder_modes.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **Quick to start** — The GPU shaders ship already built, which took a cold launch from 390 ms to 134 ms when it was measured. *macOS.* <sub>[proof](../../baud-present-macos/tests/metallib.rs) · [measured](../../MEASUREMENTS.md#the-shipped-metallib-row-1-kept)</sub>
- **Smooth resizing and zoom** — A resize or zoom step costs well under a microsecond of the core's time against an 8 ms frame. *macOS.* <sub>[measured](../../MEASUREMENTS.md#a-drag-steps-core-work-row-10-measured-no-change)</sub>
- **Light on memory** — A 200 by 50 terminal adds about 0.3 MB of real memory until it fills, because space nothing has written costs nothing. **For now:** measured on the previous core and argued, not measured again, on this one. <sub>[measured](../../MEASUREMENTS.md#storage)</sub>

## Text, fonts and emoji

Text that lines up, in any script, with fonts that work out of the box.

- **Fonts built in** — JetBrains Mono is built in, with its ligatures and its real bold, italic and bold-italic faces, so text looks right with no setup. <sub>[proof](../../baud-app/src/config.rs)</sub>
- **Ligatures that keep the grid** — Ligatures such as => and != take exactly the cells of the characters they replace, in every style and in your own fonts. <sub>[proof](../../baud-font/tests/shape.rs)</sub>
- **Double-width and double-height lines** — Banner lines drawn twice as wide, or twice as wide and twice as tall over two lines, the way vttest and DEC-era programs draw them, with line drawing that joins up and text that stays sharp. <sub>[proof](../../baud-core/tests/line_rendition.rs) · [reference](../vt-coverage.md#esc-sequences)</sub>
- **Nerd Font icons built in** — The icons prompts, file managers and git tools draw work out of the box, one cell wide. <sub>[proof](../../baud-render/tests/narrow_in_wide.rs)</sub>
- **Maths and technical symbols** — A built-in maths font draws technical symbols, including the ones Claude Code shows. <sub>[proof](../../baud-app/src/host.rs)</sub>
- **Hebrew built in** — Hebrew letters and points are drawn from baud's own monospace Hebrew, made to match the built-in font, in regular and bold. <sub>[proof](../../baud-render/tests/hebrew_embedded.rs)</sub>
- **Italic Hebrew** — Italic Hebrew is drawn upright in the regular weight. **For now:** the built-in italic faces carry no Hebrew yet. <sub>[proof](../../baud-app/src/embedded.rs)</sub>
- **Pointed Hebrew keeps every point** — Every vowel point and cantillation mark stays on its letter, even several in one cell, however the output was split and after it scrolls into history. <sub>[proof](../../baud-core/tests/cluster_bounds.rs)</sub>
- **Every script, from your Mac's fonts** — Chinese, Japanese, Korean, Devanagari, colour emoji and extra symbols draw out of the box from the Mac's own fonts, and Menlo fills in some 1,600 characters JetBrains Mono lacks. *macOS.* <sub>[proof](../../baud-app/src/config.rs)</sub>
- **A fixed list of fallback fonts** — A character the first font lacks comes from the next font that has it, one character at a time. *macOS.* **Partly:** the system fonts searched are a fixed list, so a script outside it and outside your own fonts shows boxes. <sub>[proof](../../baud-render/tests/refused_glyph.rs)</sub>
- **A box, never a blank** — A character no font can draw shows a missing-glyph box, never an empty cell. <sub>[proof](../../baud-render/tests/refused_glyph.rs)</sub>
- **Accents no font can draw** — If your font lacks one accent on a letter, the letter's other accents still show. **Partly:** an accent no installed font can draw is left off rather than shown as a placeholder, which the Unicode Standard asks for. <sub>[proof](../../baud-render/tests/missing_mark.rs)</sub>
- **Your own fonts, by name** — Name your own fonts by family, such as "Fira Code", and baud finds them among the fonts installed on your machine; list them in order, each filling in what the ones before it lack. A font file's path works too. baud's built-in fonts stay behind yours unless you turn that off. <sub>[proof](../../baud-app/src/config.rs)</sub>
- **Bold and italic in your own fonts** — With your own font, bold, italic and bold-italic text is drawn from the font's own bold and italic faces, found by its family name; a style your font has no face for is drawn from its nearest face, never faked. <sub>[proof](../../baud-app/src/config.rs)</sub>
- **Variable fonts** — Variable fonts and the TrueType, OpenType, CFF2 and collection formats are read and drawn. **Partly:** there is no setting yet to pick a weight. <sub>[proof](../../baud-render/tests/varied_face.rs)</sub>
- **A bad font can't crash it** — A broken or malicious font file cannot crash the terminal. <sub>[proof](../../baud-font/tests/hostile.rs)</sub>
- **Its own text engine** — baud reads fonts and arranges glyphs itself, each script by its own font rules, matching HarfBuzz on 576 test cases, with no third-party font library. <sub>[proof](../../baud-render/tests/script_runs.rs)</sub>
- **Sharp at every size** — The font size is in points, scaled for the display, so text stays sharp on Retina screens and keeps its size when the window moves between screens. *macOS.* <sub>[proof](../../baud-render/tests/rescale.rs)</sub>
- **Zoom** — Cmd +, Cmd - and Cmd 0 or the View menu zoom from 6 to 72 points without touching your settings file, and the window keeps its size. *macOS.* <sub>[proof](../../baud-core/tests/zoomcycle.rs)</sub>
- **Zoom on Linux** — Ctrl +, Ctrl - and Ctrl 0 zoom one step of the font size at a time, as Cmd does on a Mac, and the window keeps its size. *Linux, headless so far.* <sub>[proof](../../baud-present-wayland/tests/handshake.rs)</sub>
- **Colour emoji** — Apple Color Emoji is drawn crisply at every size, and Noto Color Emoji style fonts work too. <sub>[proof](../../baud-render/tests/apple_strikes.rs)</sub>
- **Layered colour fonts** — Layered colour fonts are drawn in their flat-colour form. **Partly:** gradient glyphs are not drawn. <sub>[proof](../../baud-font/src/colr.rs)</sub>
- **Emoji stay whole** — Families, flags, skin tones and other joined emoji each stay one character, taking the columns of one. <sub>[proof](../../baud-core/tests/marks.rs)</sub>
- **Choose how wide an emoji is** — An emoji with the emoji-style selector takes two cells, as tmux, fish and helix count it, or one if you choose. <sub>[proof](../../baud-core/tests/vs16_width.rs)</sub>
- **Keycap emoji** — Keycap emoji such as #️⃣ and 1️⃣ show. **Partly:** they stay one cell wide until their width is decided. <sub>[proof](../../baud-domain/src/vs16.rs)</sub>
- **Symbols as text or as emoji** — Choose whether symbols such as a lightning bolt draw as text or in colour; text that asks for one always gets it, and a change redraws at once. <sub>[proof](../../baud-render/tests/emoji_presentation.rs)</sub>
- **No colour font, still a symbol** — A request for a colour emoji with no colour font installed shows the plain symbol, not a box. <sub>[proof](../../baud-render/tests/emoji_presentation.rs)</sub>
- **Columns that line up** — Chinese, Japanese and Korean take two columns and marks take none, with widths from Unicode's own data, so tables, prompts and editors stay aligned. <sub>[proof](../../baud-core/tests/encoding/width.rs)</sub>
- **Ambiguous-width characters, your way** — Characters whose width differs between Western and East Asian fonts take one column or two, to match vim's ambiwidth, and programs can ask which. <sub>[proof](../../baud-core/tests/encoding/width.rs)</sub>
- **Box drawing under wide ambiguous characters** — With ambiguous characters set to two columns, box-drawing lines and blocks still draw. **Partly:** each is drawn one cell wide, in the first of its two cells. <sub>[reference](../vt-coverage.md#encoding-utf-8-or-iso-8859-1-and-8-bit-c1-controls-only-under-the-second)</sub>
- **No half characters left behind** — Overwriting half of a wide character clears the other half. <sub>[proof](../../baud-core/tests/wide_halves.rs)</sub>
- **Characters made of pieces stay together** — Accented letters, Indic conjuncts and emoji sequences stay one character: all 766 of Unicode's own test cases pass. <sub>[proof](../../baud-core/tests/encoding/graphemes.rs)</sub>
- **A thousand accented clusters at once** — About 1,024 different accented clusters fit on screen and in history at once, and those no longer shown are recycled. **Partly:** past that limit, extra accents are dropped. <sub>[proof](../../baud-core/tests/cluster_sweep.rs)</sub>
- **Broken text can't eat good text** — Broken UTF-8 shows one replacement mark per bad piece and never swallows the good character after it, disguised characters are refused, and a character split across two reads appears whole. <sub>[proof](../../baud-core/tests/text.rs)</sub>
- **Latin-1 for older systems** — Programs can switch to Latin-1 and back, with the 8-bit controls old software sends, a Latin-1 keyboard, an eight-bit Meta key, and pastes sent in Latin-1 as xterm sends them, so a pasted quotation mark can never act as a control. <sub>[proof](../../baud-core/tests/encoding/latin1.rs)</sub>
- **Line drawing from old programs** — Lines and corners from older curses programs show as lines. **Partly:** one position of the 32 still shows an underscore. <sub>[proof](../../baud-core/tests/vt100/charsets.rs) · [reference](../vt-coverage.md#esc-sequences)</sub>
- **National character sets** — Fourteen national character sets of old DEC terminals, DEC Supplemental and JIS Katakana show the right characters. <sub>[proof](../../baud-core/tests/vt100/charsets.rs) · [reference](../vt-coverage.md#esc-sequences)</sub>
- **Other old character sets** — JIS-Roman, DEC Technical and the DEC Hebrew, Greek, Turkish and Cyrillic sets are recognised. **Partly:** most of their characters still show as plain ASCII. <sub>[reference](../vt-coverage.md#esc-sequences)</sub>
- **Character set shifts** — Older programs can switch between their four character sets for one character or until told otherwise, and use the upper half of the character table, as DEC and ISO 2022 terminals allow. <sub>[proof](../../baud-core/tests/vt220/shifts.rs) · [reference](../vt-coverage.md#esc-sequences)</sub>
- **Boxes without gaps** — Box-drawing lines, blocks and shades join with no hairline gap at every size, whatever the font, and braille dots, as in btop's graphs, are sharp. <sub>[proof](../../baud-render/tests/boxes.rs)</sub>
- **Glyphs sit centred** — Each glyph is centred in its cell, and one narrower than its two cells is centred across both. <sub>[proof](../../baud-render/tests/centring.rs)</sub>
- **Smoothing to suit the colour** — Text is smoothed to suit the colour it is drawn in, so light on dark and dark on light both read cleanly. <sub>[proof](../../baud-render/tests/contrast.rs)</sub>
- **Nearly invisible text made readable** — Text too close in colour to its background is lifted to a readable contrast, keeping its hue, while colours a program chose on purpose, pictures drawn with text and the lines programs draw boxes and dividers with are left alone. Text the see-through window would make hard to read is lifted too, keeping its hue there as well, so a coloured meter's filled part stays apart from its grey track. Adjustable, or off. <sub>[proof](../../baud-render/tests/floor.rs)</sub>
- **Faint text on any theme** — Faint text fades toward the background on light and dark themes alike. <sub>[proof](../../baud-render/tests/faint.rs)</sub>
- **Every text style** — Bold, faint, italic, strikethrough, reversed and hidden text, with hidden text fully invisible on the see-through window. <sub>[proof](../../baud-render/tests/hidden_text.rs) · [reference](../vt-coverage.md#csi-operations)</sub>
- **Five underline styles** — Single, double, curly, dotted and dashed underlines, each in its own colour if a program asks. <sub>[proof](../../baud-render/tests/underline_styles.rs)</sub>
- **Blinking text** — Slow and fast blinking text, each at its own rate, held steady under Reduce Motion; with Dim Flashing Lights on it keeps blinking but dims rather than vanishes. *macOS.* <sub>[proof](../../baud-app/src/app.rs)</sub>
- **Blinking text on Linux** — Slow and fast blinking text, each at its own rate, held steady when the desktop asks for reduced motion, and an idle window with nothing blinking never wakes for it. The desktop's motion setting arrives just after launch, so text can blink in the frames before it does, where a Mac reads the setting before its first frame. *Linux, headless so far.* <sub>[proof](../../baud-app/src/timed.rs)</sub>
- **Rare text styles** — Overline, framed and encircled text, Fraktur, alternate fonts and ideogram marks are remembered and reported back to programs. **Partly:** they are not drawn yet. <sub>[proof](../../baud-core/tests/sgr/ideogram.rs)</sub>
- **Text art keeps its colours** — Colourful text art and photo previews drawn with characters keep every cell's colour, up to one distinct colour per cell of the screen. <sub>[proof](../../baud-core/tests/marks.rs)</sub>

## Keyboard, mouse and clipboard

Every key reaches the program, and copying and pasting stay safe.

- **Every key sends what programs expect** — Arrows, Home and End, Insert and Delete, Page Up and Down, F1 to F20 and the keypad, with Shift, Ctrl and Alt, in every mode programs switch between. <sub>[reference](../input-coverage.md#the-key-tables-are-extracted-not-transcribed)</sub>
- **Keypad, Backspace and Delete modes** — Programs can choose whether the keypad types digits or sends its own codes, whether Backspace sends DEL or BS and whether Delete sends DEL, as on DEC terminals and xterm, and ask which they have. <sub>[proof](../../baud-core/tests/keyboard_modes.rs) · [reference](../vt-coverage.md#csi-operations)</sub>
- **Keyboard lock and local echo** — A program can lock the keyboard, so keys send nothing until it unlocks it, or turn on local echo, so what you type shows on the screen as well as going to the program. <sub>[proof](../../baud-core/tests/keyboard_modes.rs) · [reference](../vt-coverage.md#csi-operations)</sub>
- **Option works as Meta** — Alt or Option works as Meta out of the box. <sub>[reference](../vt-coverage.md#csi-operations)</sub>
- **Keys that look alike, told apart** — Programs that ask can tell apart keys that normally send the same thing, such as Ctrl-I and Tab, and bind combinations other terminals swallow. They can choose how the arrows, function keys and keypad carry Shift, Ctrl and Alt, and ask which choice is in force. <sub>[modifyOtherKeys](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use) · [proof](../../baud-core/tests/key_modifiers.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **Full keyboard reporting** — Every key and modifier unambiguous, repeats reported, alternate keys and the text a key types, for editors such as Neovim and helix. <sub>[kitty keyboard protocol](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use) · [proof](../../baud-core/tests/kitty_encode.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **Key releases** — Programs that ask are told when a key is let go. *Linux, headless so far.* **Partly:** only the Linux version reports releases; the macOS app does not yet report releases or modifier keys pressed alone. <sub>[proof](../../baud-present-wayland/tests/handshake.rs)</sub>
- **Held keys repeat** — A held key repeats, and a program can switch repeat off. <sub>[proof](../../baud-present-wayland/tests/handshake.rs) · [reference](../vt-coverage.md#csi-operations)</sub>
- **Cmd belongs to the menus** — Cmd shortcuts go to the menus and never type into the program. *macOS.* <sub>[proof](../../baud-app/src/app.rs)</sub>
- **Input methods and dead keys** — Text you compose with a macOS input method is drawn underlined at the cursor, at the width it will take, and Return, Delete and the arrows edit it instead of reaching the shell. The cursor is always drawn after the composition: the window layer does not yet pass on where the input method puts it inside the text. *macOS.* <sub>[proof](../../baud-render/tests/composition.rs)</sub>
- **Input methods on Linux** — On Linux, text you compose with an input method such as IBus or Fcitx is drawn at the cursor, styled as GTK styles it, with the cursor where the input method puts it inside the text, or the part it marks highlighted, and the list of suggestions opens beside that cursor or that part. *Linux, headless so far.* <sub>[proof](../../baud-present-wayland/tests/handshake.rs)</sub>
- **Backspace erases the whole letter** — Backspace after a Hebrew, accented or other multi-byte letter erases the whole letter. <sub>[proof](../../baud-app/src/pty.rs)</sub>
- **The mouse in programs** — Clicks, drags, scrolls and hovers reach programs such as vim, htop and tmux, with Shift, Ctrl and Option (Alt on Linux), in every report format including pixel-precise. <sub>[SGR mouse](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use) · [proof](../../baud-core/tests/xterm/mouse.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **Programs can highlight what you drag** — A program can have the region you drag over drawn as a highlight. <sub>[proof](../../baud-app/src/keep.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **The wheel scrolls pagers** — The wheel scrolls less, man and git log, and a long fling arrives whole, even through tmux. <sub>[proof](../../baud-app/src/wheel.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **Programs know when you switch away** — Programs that ask are told when you switch to the window and away from it. <sub>[reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **Shift selects inside mouse programs** — Hold Shift to select text inside a program that uses the mouse; the choice holds until you let go. A program can ask that Shift reach it instead for every button but the one that selects. <sub>[proof](../../baud-app/src/gesture.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **Copy and paste** — Cmd-C copies the selection and Cmd-V pastes, also on a Hebrew, Russian or Greek layout, by the letter the key types with Cmd held, and letting go of a selection copies it too unless you turn that off. On Linux, Ctrl+Shift+C and Ctrl+Shift+V use the desktop's clipboard, also on a Cyrillic, Greek or Hebrew layout when the first layout listed is a Latin one, the text you select is the primary selection, and a middle click or Shift+Insert pastes it, as in other Linux terminals. <sub>[proof](../../baud-render/tests/select.rs)</sub>
- **Pastes can't run commands** — A paste is marked as one for programs that ask, so a line break in it never runs a command and pasted text can't break out of the paste. As in xterm, Escape, Control-C and the other characters your shell treats specially become spaces in a paste. <sub>[bracketed paste](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use) · [proof](../../baud-app/src/paste.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **A long paste never freezes the window** — A long paste, or one into a stopped program, is fed as the program reads it, and keys typed afterwards arrive afterwards. <sub>[proof](../../baud-app/src/pty.rs)</sub>
- **Click to move the shell's cursor** — A program can ask that a click on the command line move the cursor there, that a selection be copied the moment it is made, and that a paste be quoted for the line editor or keep its line breaks. <sub>[proof](../../baud-app/src/readline.rs)</sub>
- **Remote programs can copy to your clipboard** — Programs, even over ssh or inside tmux, can put text on your clipboard; you can turn it off, and a copy over the size limit is refused whole with a warning. <sub>[OSC 52](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use) · [proof](../../baud-app/src/clip.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **No program can read your clipboard** — Requests to read the clipboard get no answer, and no setting turns them on. <sub>[proof](../../baud-core/tests/xterm/osc.rs)</sub>
- **Links open safely** — Cmd-click opens web and mail links, whether a program marks them as links or prints the address as plain text, even one that wraps onto the next line; a link to a file is shown in Finder, never launched, and any other kind is refused. Hold Cmd over a link to see where it goes first: the link is underlined and its address shown at the bottom of the window, with the reason when a click won't open it. *macOS.* <sub>[hyperlinks](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use) · [proof](../../baud-app/src/link.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **Links open safely on Linux** — Ctrl-click opens web and mail links in your browser and mail app, whether a program marks them as links or prints the address as plain text; a link to a file is shown in your file manager, never launched, and any other kind is refused. Hold Ctrl over a link to see its address first. *Linux, headless so far.* <sub>[hyperlinks](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use) · [proof](../../baud-app/src/seat.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **A link goes where it says** — A link never leads anywhere but the address the program wrote: when the link table is full, the text stays plain. <sub>[proof](../../baud-core/tests/xterm/hyperlinks.rs)</sub>

## Scrollback, selection and resizing

Your history stays where you left it, through output, selection and resizing.

- **Scroll back through everything** — The wheel and trackpad move through the lines that scrolled off the top, with trackpad movement adding up to whole lines. <sub>[proof](../../baud-app/src/wheel.rs)</sub>
- **Find in the scrollback** — Command-F (Ctrl+Shift+F on Linux) opens a find field: every match in the history and on the screen is marked as you type, the newest is selected so a copy takes it, and Command-G or Enter steps to older ones, the window following. On macOS the field opens on your last search, made in baud or any other app, selected so that typing replaces it, and after you close it Command-G finds that search again, on from where you left it, and Command-F reopens on it. A word you compose with an input method is composed in the field. Upper and lower case match, and a letter typed with a separate accent mark matches the same letter written as one character, as the Mac's own find does. <sub>[proof](../../baud-core/tests/search.rs)</sub>
- **Reading back stays put** — New output doesn't drag you down while you read back; typing, pasting or clearing the history takes you back to the live screen. *macOS.* <sub>[proof](../../baud-app/src/app.rs)</sub>
- **A scrollbar like macOS's** — It appears while you scroll and fades away, widens when you point at it, and can be dragged or clicked; with "Show scroll bars: Always" it gets its own strip beside the text, and changing that setting in System Settings shows at once. *macOS.* <sub>[proof](../../baud-app/src/reveal.rs)</sub>
- **The scrollbar on Linux** — The same thumb as on a Mac: it appears while you scroll and fades away, widens when you point at it while looking back, and can be dragged or clicked, and a program can hide it. *Linux, headless so far.* <sub>[proof](../../baud-app/src/bar.rs) · [reference](../vt-coverage.md#csi-operations)</sub>
- **Smooth scrolling** — Output slides up instead of jumping, never more than one row behind, so a fast program never makes it lag; it can be set to jump instead. *macOS.* **Partly:** it slides only on the default GPU path, and lines with accents or ligatures jump rather than slide. <sub>[proof](../../baud-render/src/scroll.rs) · [measured](../../MEASUREMENTS.md#smooth-scrolls-per-frame-cost-measured-under-the-floor)</sub>
- **Select anything, history included** — Drag to select, double-click for a word, triple-click for a line, Shift-click to extend and Option-drag (Alt-drag on Linux) for a rectangle, reaching back into the scrollback. <sub>[proof](../../baud-render/src/select.rs)</sub>
- **You never copy text that is gone** — A selection stays on its text when a program scrolls it or the window changes height, and disappears when the text under it is redrawn, scrolled away, reset or switched. <sub>[proof](../../baud-app/src/app.rs)</sub>
- **Your selection colour** — A selection is drawn in reverse video unless you choose its colours in the config or your theme file names them; the find field, its current match and a region a program highlights take the same colours, and a program can set its own and put yours back. <sub>[proof](../../baud-render/tests/highlight_colours.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **A selection that dims in the background** — While another window has the keyboard, a selection in reverse video turns to macOS's own grey for an inactive window, light or dark as your appearance is, and comes back when you return; a selection colour you or a program chose stays as it is. *macOS.* <sub>[proof](../../baud-render/tests/inactive_selection.rs)</sub>
- **Resizing rewraps** — Making the window narrower or wider rewraps long lines instead of cutting them, and keeps your history. Rows a shorter window cut off below the cursor come back when it grows again, if they held any text. <sub>[proof](../../baud-core/tests/reflow.rs)</sub>
- **One prompt after a resize** — Resizing at a prompt your shell marks leaves one prompt, not a stack of repeats. <sub>[proof](../../baud-core/tests/resize_recorded.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **Resizing keeps your place** — Resizing while scrolled back keeps you on the line you were reading, and full-screen programs redraw into the new size as you drag. *macOS.* <sub>[proof](../../baud-app/src/app.rs)</sub>
- **Full-screen programs give your screen back** — vim, less and htop get a screen of their own, and your earlier output comes back exactly as it was when they exit. <sub>[proof](../../baud-core/tests/legacy_alt_screen.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **Headers and status lines stay still** — Scroll regions and left and right margins keep a program's headers, status lines and side panes still, and lines leaving a region at the top go into your history. <sub>[proof](../../baud-core/tests/scrollback.rs) · [reference](../vt-coverage.md#csi-operations)</sub>
- **Clear means clear** — Clearing the scrollback empties the history and leaves the screen; a reset leaves nothing of the old text behind. <sub>[proof](../../baud-core/tests/scrollback.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>

## Window, colours and bell

A see-through window that follows your Mac's appearance.

- **The Mac's own window material** — The window is drawn in the standard see-through material Apple puts behind an app's content: the desktop shows through faintly, and the window looks subdued while you work in another. Liquid Glass, frosted or clear, is one setting away. Default text stays readable over a white or a black desktop, and how see-through and how shadowed the window is are set separately for light and dark. *macOS.* <sub>[proof](../../baud-app/src/config.rs)</sub>
- **Reduce Transparency and Increase Contrast** — With Reduce Transparency on, the text area turns solid; with Increase Contrast on, text too close to its background is lifted further. They are read when baud starts and checked again while it runs. *macOS.* <sub>[proof](../../baud-app/src/app.rs)</sub>
- **Panels see-through, pictures solid** — Backgrounds programs paint, such as btop's panels, let the desktop show through, or stay solid if you prefer, while photos drawn with characters stay solid so they don't dissolve. *macOS.* <sub>[proof](../../baud-render/tests/pictures.rs)</sub>
- **See-through on Linux** — The background's see-through level and the panel and picture rules carry over to Linux, with the same shades as on macOS. *Linux, headless so far.* **Partly:** nobody has looked at the result on a real Linux screen yet. <sub>[proof](../../baud-app/src/linux.rs)</sub>
- **Only what changed, on Linux** — Each frame hands the desktop only the rows that changed, so a typed letter or a blink of the cursor copies one row of the window instead of all of it. *Linux, headless so far.* <sub>[proof](../../baud-present-wayland/tests/handshake.rs)</sub>
- **Frames in time with the screen, on Linux** — A frame is drawn when the desktop is ready for the next one, and where it reports when frames reach the screen, the cursor's blink, the bell's flash and the trails are timed for that moment, as on a Mac. *Linux, headless so far.* <sub>[proof](../../baud-present-wayland/tests/handshake.rs)</sub>
- **A margin around the text** — 8 points around the text by default, or none, with the first line below the window buttons. *macOS.* <sub>[proof](../../baud-app/src/width.rs)</sub>
- **Window titles** — A title a program sets is cleaned of hidden codes and set on the window, where the Window menu, Mission Control and accessibility tools show it. *macOS.* **Partly:** the window does not draw it in its title bar. <sub>[proof](../../baud-app/src/title.rs)</sub>
- **The folder and the program in the title** — When a program sets no title, the window's title is the folder you are in and the program running there, such as ~/src/baud — vim. A folder a shell reports is shown only when it is on this machine. **Partly:** the macOS window does not draw the title in its title bar, and nobody has run it on Linux yet. <sub>[proof](../../baud-app/src/title.rs) · [reference](../vt-coverage.md#out-of-scope-with-reasons)</sub>
- **Your title back after vim** — A program that changes the window title can save the old one first and put it back when it exits, as vim does, so the shell's title returns. <sub>[proof](../../baud-core/tests/window_reports.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **Programs can ask where the window is** — A program can ask whether the window is minimized, where it and its text sit on the screen, and how big the window and the screen are. A program cannot read the title back, so it cannot make the terminal type it. *macOS.* <sub>[proof](../../baud-core/tests/window_reports.rs)</sub>
- **Programs can move and resize the window** — A program can move, resize, minimise, raise, lower, maximise or full-screen the window, as xterm lets it. `[window] operations = "off"` stops every one, so nothing printed to the terminal can move or hide it. **Partly:** On Linux a program cannot move, raise, lower or un-minimise the window, or maximise it one way only: Wayland has no request for them. Nobody has watched any of it on a screen. <sub>[proof](../../baud-core/tests/window_ops.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **A status line under the screen** — A program can open a line of its own under the screen for its mail count, a clock or a build's state, or show baud's own line with where the cursor is, whether the keyboard is locked and whether the printer is ready. The window grows a row to hold it, so the program keeps every row it had, and gives the row back when the line goes. **Partly:** Nobody has watched the window grow on a screen: its sizing is proven as data, the line's pixels on the software renderer, and the cell path checked against the instance path. <sub>[proof](../../baud-core/tests/vt420/status_line.rs) · [reference](../vt-coverage.md#tier-2--vt220--vt420)</sub>
- **Light and dark, automatically** — baud follows System Settings and switches the moment you do, from the first frame, or you can pin one. *macOS.* <sub>[proof](../../baud-app/src/app.rs)</sub>
- **Programs follow the appearance too** — When the appearance flips, colours a program changed are reset, and programs that asked are told, so their colours can follow. *macOS.* <sub>[proof](../../baud-app/src/app.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **Light and dark on Linux** — The Linux version follows the desktop's light or dark setting and switches the moment you do, or you can pin one; a desktop with no preference gets the light colours, as GNOME's own apps do. *Linux, headless so far.* <sub>[proof](../../baud-app/src/appearance.rs)</sub>
- **Reduced motion and higher contrast on Linux** — With the desktop's reduced-motion setting on there is no default cursor trail, a plain blink and still blinking text; with its high-contrast setting on, text too close to its background is lifted further, as on a Mac. Both follow the setting the moment you change it. The motion setting arrives just after launch, so a trail can light and text can blink in the frames before it does, where a Mac reads it before its first frame. *Linux, headless so far.* <sub>[proof](../../baud-app/src/bus.rs)</sub>
- **Colours built in** — xterm's sixteen colours on dark and Modus Operandi's on light, with the five that were hard to read on their page made lighter or darker, keeping their colour, so every one but the page's own black or white reads at 4.5:1. Colours your own theme sets are drawn as written. <sub>[proof](../../baud-app/src/host.rs)</sub>
- **Your own themes** — A base16, base24, ghostty, kitty, foot, alacritty, iTerm2, Windows Terminal or X resources theme, or a list of 16 colours, for each of light and dark, recognised by what is in the file whatever its name; a broken theme, a file in another format, or a light one used for dark, is reported and baud's colours are kept. <sub>[proof](../../baud-app/src/palette.rs)</sub>
- **Programs can set and ask colours** — Programs can set and reset the palette, the default colours and the colours bold, underlined and other styled text is drawn in, by value or by X11 name such as red or lime green, ask for them, and ask whether your theme is dark or light; reverse video swaps every colour. Programs written for kitty do the same with kitty's own colour message. <sub>[proof](../../baud-core/tests/palette_query.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **Programs put your colours back** — A program can save the colours and styles it is drawing in, or the whole palette, and put them back later, ten levels deep, so a program that recolours the terminal can leave it as it found it. <sub>[proof](../../baud-core/tests/sgr_stack.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **Millions of colours** — 16, 256 and 24-bit colour, in both spellings programs use. <sub>[proof](../../baud-core/tests/sgr/subparams.rs) · [reference](../vt-coverage.md#csi-operations)</sub>
- **Reduce Motion respected** — With macOS's Reduce Motion on there is no default cursor trail, a plain blink, still blinking text and no flash for the bell, and switching it takes effect within a frame. *macOS.* <sub>[proof](../../baud-app/src/config.rs)</sub>
- **A fade for full-screen programs** — An optional fade when a full-screen program opens or exits, off by default. *macOS.* <sub>[proof](../../baud-app/src/config.rs)</sub>
- **The bell, your way** — The Mac's alert sound, a short flash or nothing; a burst rings once, and a bell in a background window never makes a sound. *macOS.* <sub>[proof](../../baud-app/src/bell.rs)</sub>
- **A bell can ask for attention** — A program can ask for the Dock icon to bounce, or for the window to come forward without taking the keyboard; on Linux either asks the desktop to bring the window to you, and the desktop decides whether it comes forward or is marked as wanting attention. <sub>[proof](../../baud-core/tests/xterm/bell_modes.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **The bell on Linux** — A bell rings the desktop's system bell while the window has the keyboard, where the desktop offers one, or shows a short flash, as the config's bell says; a burst rings once. In the background, a program that asked for it gets the window brought to your attention. *Linux, headless so far.* <sub>[proof](../../baud-present-wayland/tests/handshake.rs) · [reference](../vt-coverage.md#c0-controls)</sub>

## The cursor

Your shape and blink, and an optional trail when it jumps.

- **Your shape** — Block, underline or bar, which programs can still change, as vim does in insert mode, and which a reset returns to. <sub>[proof](../../baud-app/src/config.rs) · [reference](../vt-coverage.md#tier-2--vt220--vt420)</sub>
- **Programs can hide and recolour it** — Programs can hide, show and recolour the cursor, and every shape takes the colour. <sub>[proof](../../baud-core/tests/xterm/osc.rs) · [reference](../vt-coverage.md#csi-operations)</sub>
- **Your cursor colour** — The cursor takes the colour you set in the config or your theme file names, and the text under a block cursor its text colour, each a colour or the cell's own; a program can set its own cursor colour and put yours back, and your text colour stays. <sub>[proof](../../baud-render/tests/theme_cells.rs) · [reference](../vt-coverage.md#tier-3--xterm-extensions-in-universal-use)</sub>
- **Your blink** — The cursor follows macOS's "prefer non-blinking cursor" and its caret rate, or your own interval; it blinks only while the window is in front, shows at once when you type, and can stop after a quiet spell. *macOS.* <sub>[proof](../../baud-app/src/config.rs)</sub>
- **vim can't stop your blink** — vim's start-up and exit codes no longer stop a cursor you set to blink. <sub>[proof](../../baud-core/tests/cursor_blink_rule.rs) · [reference](../vt-coverage.md#csi-operations)</sub>
- **A blink that animates** — While blinked off, the cursor can glow like plasma, fade, burn into embers, be lifted away by a tiny flying saucer, or simply switch off. *macOS.* <sub>[proof](../../baud-render/src/caret.rs)</sub>
- **Trails** — When the cursor jumps it can leave a short trail of plasma, fire, lightning, ice, a flying saucer and more; typing never leaves one, the fiery ones never strobe, and a trail follows helix even when helix hides its cursor, on its text as output scrolls. Each is shown in [the cursor gallery](../cursor.md). *macOS.* <sub>[proof](../../baud-app/src/trail.rs)</sub>
- **Trails on the CPU path** — When the Mac's GPU can't be used, the CPU path still draws a trail, in the same shades as the GPU. *macOS.* **Partly:** every trail style is drawn as the plain stretching one there. <sub>[proof](../../baud-app/src/app.rs)</sub>
- **Trails and fades on Linux** — The cursor trails when it jumps and the full-screen fade plays when a program switches screens, as on a Mac. *Linux, headless so far.* **Partly:** the fire, plasma and other effects are drawn as the plain stretching trail. <sub>[proof](../../baud-app/src/timed.rs)</sub>

## Platforms and settings

Where baud runs, and the one settings file.

- **macOS app** — Needs macOS 26 or later, draws on the GPU with Metal and falls back to the CPU; on an older Mac it says what it needs and quits instead of crashing. *macOS.* <sub>[proof](../../baud-app/tests/macos_floor.rs)</sub>
- **Linux** — The same terminal core on Wayland, drawn on the CPU, with the keyboard, the mouse and its pointer shapes, copy and paste, and window titles. *Linux, headless so far.* **Partly:** it has run only on a headless compositor: font sizes are in pixels, and GPU drawing has not started. <sub>[proof](../../baud-present-wayland/tests/handshake.rs)</sub>
- **Your shell, set up right** — baud starts your login shell, in your home folder when opened from the Dock and with your language setting, or one command with `BAUD_CMD`. <sub>[proof](../../baud-app/src/pty.rs)</sub>
- **A clean environment** — Programs see baud with full colour, and nothing of the terminal you started it from. <sub>[proof](../../baud-app/src/pty.rs)</sub>
- **One optional settings file** — Keep only what you change in one file; baud never reads a stray file from the folder it started in. <sub>[proof](../../baud-app/src/config.rs)</sub>
- **A typo never stops baud starting** — An unknown setting is skipped with a warning naming it, a bad value falls back and baud says so, and settings from older versions are explained rather than dropped. <sub>[proof](../../baud-app/src/config.rs)</sub>
- **Saved settings show at once** — Save the settings file, or a theme or font file it names, and the open window follows: edited in place, saved by swapping in a new file, or created for the first time. - **An example file that does what it says** — The example settings file is checked by a test to do what its comments say. <sub>[proof](../../baud-app/src/config.rs)</sub>

## Where baud is behind

Where other terminals do more today, and what baud does not do yet, with a
link where the [roadmap](../roadmap.md) plans it.

- **A fixed list of fallback fonts** — most terminals search every installed font for a character the others lack; baud searches a fixed list.
- **Layered colour fonts** — kitty and wezterm draw the gradient form of layered colour fonts.
- **Rare text styles** — ghostty and wezterm draw overlined text.
- **Key releases** — the macOS app does not yet tell programs when a key is let go, or when a modifier key is pressed alone. [Roadmap](../roadmap.md#keyboard-mouse-and-clipboard)
- **Links open safely** — the pointer keeps its shape over a link, where iTerm2 and WezTerm show a pointing hand.
- **Window titles** — every other terminal draws the window title in its title bar. [Roadmap](../roadmap.md#window-colours-and-bell)
- **Solid image backgrounds** — foot draws the solid background on its see-through window too. [Roadmap](../roadmap.md#pictures)
- **Linux** — the Linux version has run only headless, with no GPU drawing yet. [Roadmap](../roadmap.md#platforms-and-settings)
- **Right-to-left text** — Hebrew and Arabic are shown left to right, in the order the program sent them; reordering is not built yet. [Roadmap](../roadmap.md#text-fonts-and-emoji)
- **More than one window** — baud opens one window; Cmd-N for another is not built yet. [Roadmap](../roadmap.md#window-colours-and-bell)
